
### Agent的滚雪球效应

滚雪球效应体现在两个层面：

  1. token 消耗越来越大：Step 1 的 prompt 可能 500 token，Step 4 可能已经 2000
  token，Step 8 可能 4000+ token。每次推理都在为历史付 token 费。
  2. 模型注意力被稀释：越到后面，模型要"记住"越多的旧信息，小模型尤其容易在长上
  下文中跟丢重点。

  这就是为什么生产级 Agent 框架不会无脑全量追加历史，而是用几种策略控制膨胀：

  ┌────────────┬─────────────────────────────────────────────────────────────┐
  │    策略     │                            做法                             │
  ├────────────┼─────────────────────────────────────────────────────────────┤
  │ 滑动窗口    │ 只保留最近 N 轮，最旧的历史丢掉                                  │
  ├────────────┼─────────────────────────────────────────────────────────────┤
  │ 摘要压缩    │ 把旧步骤压缩成一句摘要（"已获取                                  │
  │            │ 15×23=345，已查询监督学习定义"），替代原始对话                    │
  ├────────────┼─────────────────────────────────────────────────────────────┤
  │ 结构化记忆   │ 工具返回的结果存到独立存储，只把"当前状态"注入                     │
  │            │ prompt，不重复注入原始对话                                     │
  ├────────────┼─────────────────────────────────────────────────────────────┤
  │ 截断        │ 超出 token 上限时直接裁掉最早的内容                             │
  └────────────┴─────────────────────────────────────────────────────────────┘

  当前这个教学实现没做任何压缩，是故意把机制暴露出来的——你感受到的"傻"恰恰是教学
  目的：先理解 naive 实现的问题，才能理解生产方案为什么需要那些额外复杂度。
