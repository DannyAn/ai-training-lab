本课程系列的设计理念是：

```
你的能力 = 会跑通闭环 × 能解释每一环 × 会做实验改进
```

01_mnist 就是**第一个闭环**。它用最简单的手写数字识别任务，让你第一次完整经历：

```
原始数据 → 小批量加载 → 前向传播 → 损失计算 → 
反向传播 → 参数更新 → 验证 → 保存权重 → 恢复推理
```

这个闭环是所有后续课程（CIFAR-10、RNN、Transformer、GPT、微调、Agent）的**不变骨架**。在这门课里欠下的理解债，后续每一课都会向你讨还。

## 核心骨架：5 步训练循环

请把这 5 步刻在脑子里，它们会贯穿整个系列：

| 步骤 | 代码映射 | 你的理解重点 |
|------|----------|--------------|
| 1. 前向传播 | `logits = model(x)` | 输入图片 → 输出 10 个分数 |
| 2. 计算损失 | `loss = criterion(logits, y)` | 比较分数和真实标签的差距 |
| 3. 反向传播 | `loss.backward()` | 自动计算每个参数对损失的梯度 |
| 4. 更新参数 | `optimizer.step()` | 根据梯度微调权重，让损失下降 |
| 5. 验证/评估 | `model.eval(); compute accuracy` | 在没见过的数据上检验学习效果 |

训练文件 `train.py` 就是把这张表循环了 N 次。

## 你必须搞清的三个关键认知

### 1. 模型输出的是分数，不是概率
最后一层没有 Softmax。`CrossEntropyLoss` 需要原始分数（logits），内部自动进行数值稳定的概率转换。推理时你用 `argmax(logits)` 就得到了最可能的类别，和用概率后再 `argmax` 结果相同。

### 2. 你保存的只是权重，不是整个应用
`mnist_cnn.pt` 里面只有 `state_dict`（参数字典）。要恢复推理，你必须同时拥有：
- 完全相同的模型类定义 `MNISTCNN`
- 完全相同的图像预处理（Normalize 参数）
- PyTorch 环境

这就是为什么模型权重不能独立分发。

### 3. 训练、验证、测试是三个不同的概念
- **训练集**：用来让模型学习（更新参数）
- **验证集**：用来调超参数、监控过拟合（本课从训练集切出 10%）
- **测试集**：模型完全确定后，做一次最终评估（本课为教学简洁暂未加载，实验环节会让你加上）

把验证集当成最终水平拿出来说，是面试中的致命伤。

## 动手实验：从“会用”到“会想”

**实验纪律**：每次只改一个变量，先写下你的假设再跑实验。

### 实验 1：Dropout 的真相
将 `train.py` 中 Dropout 改为 `0`、`0.2`、`0.7`，分别记录训练损失曲线和验证准确率。
- 假设：Dropout 为 0 时，验证准确率会___？训练损失会___？
- 做完后回答：Dropout 是解决什么问题的手段？

### 实验 2：批次大小的蝴蝶效应
将 batch_size 改为 `8`、`64`、`256`，观察每 epoch 耗时和最终验证准确率。
- 假设：batch size 越小，训练会___（快/慢）且___（稳定/震荡）？
- 思考：batch size 和梯度更新次数有什么关系？

### 实验 3：补上真正的测试
加载 MNIST 官方测试集（`train=False`），在你用验证集选出最佳 epoch 后，只测试一次。
- 这个测试分数和你的验证分数差了多少？如果有差距，可能的原因是什么？

### 实验 4：最佳权重 vs 最终权重
当前代码保存的是最后一个 epoch 的权重。修改代码，让它同时保存验证准确率最高时的权重，并比较两者在测试集上的表现。你会提前碰到“早停”的思想。
